# Identity and Namespace Model

Mems uses request identity to locate memory ownership boundaries. The API
accepts an optional generic `namespace` path (`string[]`) for caller business
context, such as `["projects", "prj_abc123"]`. Mems combines
validated identity and these path segments into an immutable internal
`MemoryNamespace`. Callers never send or override the complete internal value.

The namespace is a storage partition key. It provides consistent namespacing
across adapters, while business authorization remains the caller application's
responsibility. The application must authenticate the caller and decide which
identity it is allowed to use. Mems then applies that identity consistently to
SQL, Redis, and Qdrant operations.

## Identity Fields

| Field | Type | Role |
| --- | --- | --- |
| `tenant_id` | string or null | tenant / organization boundary |
| `user_id` | string or null | user boundary |
| `agent_id` | string | agent boundary; required |
| `session_id` | string or null | write-side provenance; not a recall boundary |

`tenant_id`, `user_id`, and `agent_id` are identity dimensions. In multi-user
deployments, the caller application should derive them from trusted
authentication and authorization context rather than accepting arbitrary
client-provided values. Missing optional identity values form a distinct
default identity partition; they do not act as wildcards or authorization
checks.

## MemoryNamespace

`MemoryNamespace` is an immutable value object generated by Mems from the
validated identity and optional request `namespace` segments. Its canonical
versioned path can be represented as:

```text
("v1", "tenant", <tenant_id>, "user", <user_id>, "agent", <agent_id>,
 "memories", ...<namespace>)
```

The `namespace` request field is a list of opaque path segments, not a complete
storage namespace or a permission grant. Omitted or empty `namespace` selects
the default partition for that identity; it does not search child namespaces.
Write and query use the same path to address the same partition. The implementation
encodes absent optional identity values distinctly from literal values and
serializes segments without delimiter ambiguity. Memory type, timestamps, importance, and evidence lineage
remain record attributes so a recall can search across memory types.

For example, an application may pass `["projects", "prj_abc123"]`; use stable
identifiers rather than mutable display names. Mems does not assign meaning to
these segments and does not add product-specific fields such as `project_id`.

The value object should expose immutable tuple segments, for example:

```python
class MemoryNamespace(BaseModel):
    model_config = ConfigDict(frozen=True)
    segments: tuple[str | None, ...]
```

`session_id` is excluded from the long-term namespace so memories can be
recalled across sessions. L0 may add it to its per-session cache key.

## Authorization and Shared Memory

Mems does not define application roles, team membership, or ACL rules. For a
private user memory, the caller authorizes the user and passes the corresponding
identity. For team or application-shared memory, the caller must authorize the
shared owner and provide an identity that represents that owner. A free-form
visibility label is not an authorization check.

The caller application must authorize the business context before supplying
namespace segments. Mems treats them as a storage partition selector, not an
ACL. Recall uses the exact identity and namespace path; no wildcard or prefix
search is implied. For shared project memory, callers must also use an identity
that represents the shared owner: matching namespace segments alone do not
cross tenant, user, or agent boundaries.

## Relationship to Storage

```text
L0 Redis key   : namespace + session_id
L1 SQL         : tenant_id / user_id / agent_id / session_id + namespace
L2 SQL         : tenant_id / user_id / agent_id + namespace
Qdrant payload : identity and namespace filters for vector candidates
L3 JSONL       : original identity fields and archive provenance
```

Identity columns remain available for explicit filtering, indexing, reporting,
and migrations. `MemoryNamespace` supplies the shared canonical partition
representation; it does not replace identity fields or authorize access by
itself.

## Checklist

- [ ] All writes and recalls use identity derived from trusted application context.
- [ ] `MemoryNamespace` is generated by Mems from validated identity and namespace segments, and immutable after creation.
- [ ] SQL, Redis, and Qdrant use the same canonical namespace rules.
- [ ] Missing optional identity dimensions have documented, deliberate semantics.
- [ ] `session_id` remains provenance and is not used to partition long-term recall.
- [ ] Shared memory access is authorized by the caller application before Mems access.
